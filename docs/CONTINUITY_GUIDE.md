# دليل استمرارية تطوير وتشغيل جربوع

## الملخص التنفيذي

هذا الدليل موجّه للمطور الذي يستلم المشروع لاحقاً. الهدف هو أن يبدأ من بنية واضحة، وأن يحافظ على خصوصية المستخدمين، وأن يتجنب تكرار تعديل ترحيلات مطبقة أو رفع بيانات تشغيلية إلى GitHub.

## 1. نموذج البيانات وتدفق الطلب

ينشئ العميل طلباً ضمن نطاق حماة. يعيّن الخادم العرض للسفير الأقرب المتصل لمدة محددة، ثم ينتقل إلى التالي عند الرفض أو انتهاء المهلة. عند قبول العرض يُحسم التعيين داخل قاعدة البيانات، وبذلك لا يمكن قبول الطلب من أكثر من سفير. يرسل السفير مواقع GPS الموثوقة أثناء الرحلة؛ تحفظ نقطة حية للمتابعة ومقاييس مجمعة للمسافة والوقت، بينما يرى العميل مساراً محدوداً خاصاً بطلبه فقط.

| المرحلة | الملف أو الخدمة الأساسية | ضابط السلامة |
|---|---|---|
| التسجيل والتحقق | `server/routers.ts` | عدد محاولات ورموز مؤقتة وصلاحيات دورية |
| الطلب والعرض | `supabase/migrations/*offer*` و`server/routers.ts` | حسم ذري للتعيين وعدم كشف العرض لغير السفير المعني |
| الموقع الحي | `server/jarbou3-driver-location.ts` | التحقق من الدقة والنطاق وصلاحية السفير |
| خريطة العميل | `components/hama-map.*` | العميل يرى طلبه النشط فقط |
| التسليم | `verifyDeliveryOtp` ورفع الإثبات | رمز تسليم وصورة إثبات مرتبطة بالطلب |

## 2. خطة العمل اليومية للمطور

ابدأ دائماً بقراءة سجل المهام الحالي ثم حدّد ما إذا كان التغيير يطال الهاتف أو الخادم أو قاعدة البيانات أو بوابة الإدارة. أبق التغييرات صغيرة وواضحة. عند الحاجة إلى تعديل قاعدة البيانات، أضف ترحيلاً جديداً باسم تاريخي في `supabase/migrations/`؛ لا تعِد كتابة ترحيل مطبق لأن بيئة الإنتاج قد سبق أن نفذته.

```bash
# فحص محلي إلزامي قبل الحفظ
pnpm check
pnpm test
pnpm build
```

بعد الفحص، احفظ checkpoint وصفياً. عند ظهور خلل في الخادم، افحص `.manus-logs/devserver.log` أولاً؛ ولا تقتل عمليات النظام أو المتصفح عشوائياً. عند توقف معاينة Expo، أعد تشغيل خادم التطوير ثم تحقق من `http://127.0.0.1:3000/api/health` و`http://127.0.0.1:8081`.

## 3. قاعدة البيانات والترحيلات

قاعدة البيانات التشغيلية هي Supabase، وليست نسخة GitHub. طبّق ترحيلات DDL فقط بعد مراجعة أثرها، ولا تدرج بيانات اختبارية في الإنتاج. دوال قاعدة البيانات التي تستخدم `SECURITY DEFINER` يجب أن تتحقق من المستخدم الحالي بوضوح، وأن تُسحب منها صلاحية التنفيذ العام إن كانت دوال مشغّلات داخلية فقط.

عند العمل على التتبع، احرص على أن تكون قراءة مسار GPS مقيدة بالعميل صاحب الطلب أو السفير المعيّن أو المدير. لا تفتح جداول المواقع أو المسارات للاستخدام العام.

## 4. بوابة الإدارة

الرابط الأساسي هو `/admin`. عند التهيئة الأولى يختار المالك كلمة مرور من داخل البوابة، وتحفظ كتجزئة bcrypt في قاعدة البيانات. لا تُعد إلى استخدام كلمة مرور نصية أو رابط استرداد كبديل للتدفق الطبيعي. جلسة البوابة موقعة من الخادم؛ لذلك تبقى قيمة توقيع الجلسة سرية وخارج Git.

## 5. سياسة الأمان والأسرار

| العنصر | المكان الصحيح | ممنوع |
|---|---|---|
| مفاتيح Supabase وGitHub وكلمات المرور | مدير أسرار المنصة أو GitHub Secrets | `README.md`، الاختبارات، السجلات، ملفات المصدر |
| ملفات البيئة | جهاز المطور أو إعدادات النشر | رفع `.env` أو أي نسخة منه |
| صور الهوية والوثائق والتسجيلات | Storage وقاعدة البيانات وفق سياسة الاحتفاظ | GitHub أو الملفات المحلية الدائمة |
| النسخ الاحتياطية | مستودع GitHub خاص للكود فقط | بيانات العملاء أو تصدير قواعد البيانات غير المشفر |

قبل أي رفع، نفذ فحص الملفات المتعقبة:

```bash
git ls-files | grep -E '(^|/)(\.env|.*\.(pem|key|p12|p8|jks|mobileprovision)|.*\.(secret|secrets))$' || true
```

يجب أن تكون النتيجة فارغة. قواعد `.gitignore` تستبعد `.env` و`.env.*` والمفاتيح وملفات الأسرار، لكنها لا تعالج تسريباً حدث بالفعل؛ عند تسريب مفتاح، أبطله من المصدر ودوّر البديل فوراً.

## 6. النسخ الاحتياطي والاسترداد

المستودع الخاص يحمي الشفرة من الفقد التشغيلي، لكنه ليس بديلاً عن نسخ قاعدة البيانات وStorage. أنشئ نقطة استعادة بعد كل ميزة مكتملة، واستخدم تاريخ الإصدارات للرجوع إلى نسخة معروفة. يجب أن يكون الوصول إلى GitHub محمياً بمصادقة ثنائية أو مفتاح مرور، وأن يقتصر منح الصلاحيات على من يحتاج التطوير فعلاً.

## 7. قائمة تسليم للمطور التالي

1. اقرأ `README.md` و`SECURITY.md` و`todo-ezmlh0n7.md` أولاً.
2. شغّل الاختبارات والبناء قبل لمس منطق الرحلات أو المصادقة.
3. افهم الترحيل المرتبط قبل تعديل قاعدة البيانات.
4. لا تطلب مفاتيح عبر الدردشة ولا ترفعها إلى Git.
5. وثّق كل قرار معماري أو تغيير أمني في هذا الدليل أو في ملف جديد داخل `docs/`.
